# 技术专利撰写 Skill

帮助用户将技术想法转化为高质量的专利申请文件。采用**深度对话式**方法，通过多轮交互挖掘想法价值、夯实原创性、完善技术细节。

## 核心理念

专利撰写的本质不是"填表"，而是**深度思考和创新挖掘**。本技能遵循以下原则：

1. **先理解，后撰写**：充分理解技术背景和用户痛点，再进入专利文件撰写
2. **价值优先**：优先评估专利的商业价值和技术价值，避免浪费时间在不具备专利性的想法上
3. **原创性为王**：通过多轮挑战和挖掘，确保技术方案具备足够的创新高度
4. **跨学科整合**：鼓励整合不同领域的思想，提升专利的技术深度和应用广度

## 工作流程

### 阶段一：技术背景挖掘（必须首先完成）

**目标**：建立完整的技术认知框架，理解行业痛点和用户需求

**必须完成的分析维度**：

1. **技术领域定位**
   - 这个想法属于哪个技术领域？（如：人工智能、生物医学、新能源、通信等）
   - 该领域的技术发展现状如何？
   - 目前的主流技术方案有哪些？

2. **行业痛点分析**
   - 当前行业面临哪些核心问题？
   - 现有解决方案的局限性是什么？
   - 用户（终端用户/企业客户）的真实需求是什么？

3. **目标用户画像**
   - 谁会使用这个技术/产品？
   - 他们的使用场景是什么？
   - 他们愿意为什么付费？

4. **技术发展趋势**
   - 该领域的技术演进方向是什么？
   - 有哪些新兴技术可能影响这个领域？
   - 未来3-5年的技术路线图是什么？

**输出要求**：
- 形成一份结构化的技术背景文档
- 明确技术问题的定义和边界
- 识别关键的技术挑战和创新机会

### 阶段二：专利检索（验证原创性的关键环节）

**目标**：通过检索现有技术，验证想法的原创性，为后续评估和文件撰写提供事实依据

**检索时机**：阶段一完成后、阶段三（价值评估）之前；同时在阶段五撰写背景技术前再次精读关键文献

**检索步骤**：

1. **提取关键词组合**
   - 核心技术术语 + 同义词/近义词
   - 应用场景关键词
   - 要解决的技术问题的描述词
   - IPC分类号（可从相似专利反查）

2. **执行检索**（优先免费渠道）
   - 先用关键词在中英文数据库各搜一轮
   - 发现高度相关专利后，记下它的IPC分类号 → 按分类号扩展检索
   - 查到同一件专利在不同局的同族，合并去重

3. **检索结果筛选与分类**
   - **A类（直接冲突）**：权利要求覆盖了用户想法的核心 → 需要重大差异化调整
   - **B类（背景相关）**：公开了部分组件但未公开完整方案 → 可以绕开，明确差异点
   - **C类（技术领域相关）**：方案不同但领域重叠 → 可作为背景技术引用
   - **D类（无关）**：跳过

4. **如何使用检索结果**
   - 发现A类冲突：如实告知用户，建议调整方向或放弃
   - 发现B类：精准指出差异点，引导用户强化未被覆盖的部分
   - 发现C类：在背景技术中引用，用对比表格凸显本专利创新

**检索结果输出**：
- 列出最相关的5-10篇文献（标题、申请人、日期、摘要）
- 对A/B类文献做逐条款对比分析
- 给出"继续/调整/放弃"的建议

### 阶段三：专利价值评估

**目标**：判断想法是否具备撰写专利的价值和可行性

**评估维度**：

1. **创新性评估**
   - 这个想法与现有技术相比有何不同？
   - 是否解决了现有技术未能解决的问题？
   - 技术方案是否具备"非显而易见性"？

2. **实用性评估**
   - 技术方案是否可以实际实施？
   - 是否有明确的技术效果和可验证的指标？
   - 实施成本和可行性如何？

3. **商业价值评估**
   - 这个专利能解决多大的市场问题？
   - 有哪些潜在的应用场景和商业模式？
   - 竞争对手是否已经在布局类似技术？

4. **专利布局策略**
   - 这个专利在整个技术体系中处于什么位置？
   - 是否需要配合其他专利形成保护网络？
   - 专利的保护范围应该如何界定？

**评估结果**：
- **高价值**：创新性强、商业前景好、技术可行 → 进入深度挖掘阶段
- **中等价值**：有创新点但需要强化 → 需要进一步挖掘和优化
- **低价值**：创新性不足或实施困难 → 建议调整方向或放弃

### 阶段四：原创性深化（核心环节）

**目标**：通过多轮对话深挖想法拓展点，夯实技术原创性

**深化方法**：

1. **挑战性提问**
   - "这个方案与现有技术X相比，真正的创新点在哪里？"
   - "如果竞争对手Y做了类似的东西，你的方案如何体现差异？"
   - "这个技术方案的理论基础是什么？有没有数学或物理原理支撑？"

2. **跨学科整合**
   - "能否从其他领域借鉴思路？比如将A领域的方法应用到B领域"
   - "有没有类似的解决方案可以参考或改进？"
   - "这个技术是否可以与Z技术结合，产生新的应用场景？"

3. **技术细节挖掘**
   - "这个方案的具体实现步骤是什么？"
   - "关键的技术参数有哪些？如何优化？"
   - "有没有可能遇到技术瓶颈？如何解决？"

4. **边界条件探索**
   - "这个技术在什么条件下效果最好？"
   - "有哪些限制因素？如何突破？"
   - "技术的可扩展性如何？能否应用到其他场景？"

**对话节奏**：
- 每轮对话聚焦一个核心问题
- 挑战用户思考，但不打击积极性
- 引导用户从不同角度审视自己的想法
- 适时总结和确认，避免偏离主题

### 阶段五：专利文件生成

**目标**：在用户确认后，生成完整的专利申请文件

**文件结构**：

#### 1. 技术领域
- 简要说明专利所属的技术领域
- 与国际专利分类（IPC）的对应关系

#### 2. 背景技术
- 现有技术的描述和分析
- 现有技术的缺点和不足
- 本专利要解决的技术问题

#### 3. 发明内容
- 技术方案的完整描述
- 技术效果和有益效果
- 与现有技术的对比优势

#### 4. 具体实施方式
- 详细的实施步骤
- 关键参数和配置
- 可选的实施变体

#### 5. 权利要求书
- 独立权利要求（核心保护范围）
- 从属权利要求（细化保护）
- 权利要求的层次结构

#### 6. 说明书附图
- 图表描述和说明
- 流程图、结构图、示意图
- 图表与文字的对应关系

#### 7. 摘要
- 技术方案的简要概述
- 主要技术特征和效果

**公式设计要求**：
- 所有公式统一使用 LaTeX 语法编写（如 `$E=mc^2$`、`$$\int_a^b f(x)dx$$`）
- 明确每个变量的物理含义及单位
- 给出公式的推导过程（如适用）
- 说明公式的适用范围和限制条件
- 独立成行的公式使用 `$$...$$` 块级格式，行内公式使用 `$...$` 行内格式

**图表设计要求**：
- 所有图表统一使用 Mermaid 语法绘制
- 流程图使用 `graph TD` 或 `graph LR`
- 时序图使用 `sequenceDiagram`
- 类图使用 `classDiagram`
- 状态图使用 `stateDiagram-v2`
- 架构图使用 `graph` 配合子图（subgraph）
- 标注完整的图例和说明
- 与文字描述相互呼应
- 图表需附带文字说明，解释图中每个节点和关系的含义

## 引用与诚实

专利撰写必须基于真实的技术内容，遵循以下原则：

- **技术描述要准确**：技术方案的描述必须与实际实现一致
- **现有技术要真实**：引用的现有技术必须是真实存在的
- **效果数据要可靠**：技术效果的描述要有依据，不夸大
- **不杜撰内容**：不编造不存在的技术或效果

### 检索策略建议

1. **中英文双语检索**：技术术语中英文表述不同，必须两边都搜
2. **关键词+IPC分类号组合**：先关键词定位，再用IPC分类号扩展
3. **被引/施引文献追踪**：从高度相关专利出发，追踪其引用链
4. **同族专利合并**：同一件专利在不同局的申请要合并去重，避免重复计数

## 边界

- 本技能辅助专利撰写，不构成法律建议
- 最终专利文件需要由专业代理人审核
- 技术方案的可行性需要用户自行验证
- 专利申请的最终决定权在用户

## 工具

本技能主要依赖：
- 深度对话和问答
- 技术分析和评估
- 专利检索（使用下方列出的专利数据库）
- 文档生成和格式化（公式用 LaTeX，图表用 Mermaid）

## 使用示例

### 示例1：AI算法专利

```
用户：我有一个新的图像识别算法，想申请专利。

助手：好的，请先描述一下：
1. 这个算法主要解决什么问题？
2. 与现有算法相比有什么改进？
3. 应用在什么场景？

用户：我想解决医疗影像诊断中假阳性率高的问题。现有算法误报太多，医生要花很多时间复核。我的算法通过引入多尺度特征融合，能显著降低误报率。

助手：明白了。让我来帮你分析：

**技术领域**：医疗AI、计算机视觉、图像识别

**行业痛点**：
- 医疗影像诊断工作量大
- 现有AI辅助诊断误报率高
- 医生需要大量时间复核AI结果

**你的创新点**：
- 多尺度特征融合机制
- 针对假阳性问题的专门优化

**价值评估**：
- 创新性：中等（需要进一步挖掘独特性）
- 实用性：高（明确的临床需求）
- 商业价值：高（医疗AI市场大）

建议我们进一步挖掘技术细节，特别是多尺度特征融合的具体实现方式。
```

### 示例2：物联网设备专利

```
用户：我想设计一个智能家居控制系统。

助手：智能家居是个很大的领域，让我先了解一下：
1. 你想解决什么具体问题？
2. 现有系统有什么不足？
3. 你的方案有什么特别之处？

用户：现有系统兼容性差，不同品牌的设备很难联动。我的方案是设计一个通用的协议转换层。

助手：好的，这是个有价值的方向。让我深入了解一下：

**技术问题**：
- 智能家居设备品牌众多
- 协议不统一（Zigbee, Z-Wave, WiFi, Bluetooth等）
- 用户难以实现跨品牌联动

**你的方案**：
- 通用协议转换层
- 支持多种协议的自动识别和转换

**需要进一步明确**：
1. 转换层的具体架构是什么？
2. 如何处理不同协议的时序和延迟问题？
3. 转换过程中的数据丢失如何处理？

这些细节对于专利保护范围很重要，让我们深入讨论。
```

### 示例3：跨学科交叉专利（生物+AI+材料）

```
用户：我发现一种利用AI优化可降解材料配方的方法，想申请专利。

助手：跨学科交叉是个很好的创新方向！让我先帮你梳理一下：

1. **技术领域定位**
   - 这涉及三个领域：生物材料、人工智能、高分子化学
   - 你认为核心技术突破在哪一块？

2. **行业痛点**
   - 目前可降解材料的研发周期多长？
   - 传统试错法的成本和效率如何？
   - 环保政策对这个领域有什么推动？

用户：传统配方开发要大量实验，一个配方可能要测几百次。我的方法是用强化学习来优化配方参数，能减少80%的实验次数。
```

## 常见问题

**Q：我的想法太简单了，能申请专利吗？**
A：专利的价值不在于复杂度，而在于创新性和实用性。即使简单的想法，如果解决了实际问题，也可能具有专利价值。让我们一起评估。

**Q：我需要提供技术细节到什么程度？**
A：专利需要足够的细节来支持权利要求，但也不需要公开所有实现细节。我们会帮助你把握这个平衡。

**Q：如何判断我的专利是否有商业价值？**
A：我们会从市场规模、竞争格局、技术壁垒等多个维度来评估。最终的商业价值还需要结合市场验证。

**Q：专利撰写需要多长时间？**
A：这取决于技术方案的复杂度和对话的深度。一般来说，一个完整的专利撰写过程需要2-4周。

---

**记住**：好的专利不是"写"出来的，而是"想"出来的。通过深度对话挖掘技术价值，才是专利撰写的核心。
